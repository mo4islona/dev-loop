## How to write it
- Make the smallest change that meets the acceptance criteria. Add no abstraction, option,
  layer or state that the task does not need now.
- Before you write a helper, look for one in this repo, its dependencies or the standard
  library.
- Match the surrounding code: naming, error handling, comment density, test style.
- Readability over compactness: blank lines between logical blocks, a named intermediate
  for any expression with a meaning, no crammed one-liners.
- Comments only for what the code cannot show.
- Add or update tests for the behaviour you change. Run `{{TEST_CMD}}`.
- Do not commit, push, make a worktree, or touch files outside the task.
